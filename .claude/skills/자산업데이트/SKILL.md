# 자산업데이트 — 노션 SOP 3종 → import JSON

## SSOT — 노션 SOP 3종 (2026-07-06 제정)

"내 자산" 데이터의 원본은 아래 노션 페이지 3개다. 금융지식 세션(계좌캡처 반영)·코드 세션·앱이
**모두 이 3페이지를 공통으로 갱신·참조**한다.

| 구분 | 페이지 ID | 역할 |
|---|---|---|
| 계좌 종목 현황 | `3955efd0-e462-81da-b7f3-cbd905a15dfd` (📊 14RAE 계좌 종목 현황 SOP) | 계좌×종목×수량 SSOT |
| 배당금 | `3865efd0-e462-81c4-9a72-c9bbc70dcea0` (💹 14RAE 배당기준 마스터) | 확정 DPS·배당률·지급시기 |
| 월매수 | `38f5efd0-e462-81e8-a1a0-e35bfb864dc6` (📈 월자동매수 현황 & 월배당 비교) | ETF모으기 매수계획·금액 |

매도이력 대장: `38d5efd0-e462-81ff-a961-cb9ce0f22f4f` — import JSON 생성 **전에** 우선 확인한다.

이 3페이지 밖의 계좌·수량 출처(오래된 세션 기록 등)는 참고만 하고, SSOT와 충돌하면 SSOT를 따르되
애매하면 사용자에게 확인한다.

## 처리 순서

1. SOP 3페이지 조회 → 2. 매도이력 대장 확인 → 3. import JSON 생성 → 4. 자가검증 → 5. SendUserFile 전달.

**개인 보유 데이터이므로 저장소에 절대 커밋하지 않는다. 채팅 파일로만 전달한다.**

## ⚠️ 전달 전 자가검증 (2026-07-19 실수 복기로 제정)

생성 스크립트가 다음을 출력해 확인한 뒤에만 전달한다:

- (a) `monthlyQty > 0` 행 수가 월자동매수 SOP의 매수계획 종목 수와 부합하는가
- (b) 3개 SOP가 각각 실제로 반영됐는가
  - 계좌현황 → `qty`
  - 배당마스터 → `confirmedDps` / `payPeriod`
  - 월매수 → `monthlyQty` / `buyFreq` / `buyDay`
  - 납입금 → `contributions`

> 실사례(2026-07-18): 보유수량·DPS 재구성에 집중하다 월매수 SOP를 조회하지 않아 76행 전부
> `monthlyQty=0`인 파일을 전달했고, 사용자가 앱에서 "월매수 계획 —" 빈 화면을 보고서야 발견됐다.

## import JSON 스키마

```json
{
  "rows": [{
    "account": "삼성_DC", "symbol": "...", "qty": 0, "avgPrice": 0,
    "monthlyQty": 0, "buyFreq": "매월", "buyDay": "25일",
    "confirmedDps": 0, "payPeriod": "월초", "divType": "실확", "divExpiry": "YYYY-MM"
  }],
  "goalAmount": 0, "expectedReturn": 0,
  "contributions": {"계좌명": 0},
  "divHistory": {"YYYY-MM": 0},
  "dataAsOf": "", "importedAt": ""
}
```

- **계좌명**: 사용자 시트 표기를 그대로 쓴다(삼성_DC, 삼성_연금, 삼성_IRP, KB_일반, KB_ISA, 신한_일반 …).
  사이트가 목록 밖 계좌명도 보존한다.
- **`monthlyQty`**: 1회 매수 수량. **`buyFreq`**: 매수주기("매월"/"매주"/"매일" → 월 1/4/22회로 환산).
  **`buyDay`**: 표시용 문자열("화요일"/"25일") — 계산에 미사용.
- **`divType`**(실확/특별/고정)·**`divExpiry`**(특별배당 만료 YYYY-MM): 노션 배당기준 마스터 기준.
- **`divHistory`**: 월별 확정 배당 총액 이력(연도별 배당추이 표에 표시).
- **`contributions`**: 계좌별 월 납입금(연금저축 등 배당 외 현금 납입). 자급률 탭에서 해당 계좌
  "수입"에 배당과 함께 합산된다.
- 매수계획만 있고 보유수량 미상인 종목은 `qty: 0` + `monthlyQty > 0` → 평가액 0·월매수만 집계.

### 이력 필드 (A8, 2026-07-16)

노션에 "자산 스냅샷 이력"(사용자가 앱의 "📋 이력 SOP 요약 복사"로 붙여넣어 만든 페이지)이 있으면
그 값을 채워 재설치 후에도 이력이 복원되게 한다:

- `snapshotHistory` — 월별 `[{month, value, monthlyDiv}]`
- `dailyHistory` — 일별 `[{date, value, monthlyDiv}]`
- `changelog`

없으면 필드를 생략한다(앱이 기존 localStorage 이력을 유지함).

**`divHistory`의 우선 출처(2026-08-08 추가)**: 배당기준 마스터 SOP의 **"📊 월별 확정 배당금 실적"**
표(`종목조회` 스킬 C항목이 매달 30일에 자동 채움)가 있으면 그 값을 최우선으로 쓴다. 이 표에 없는
과거 월은 기존 스냅샷 이력 페이지 값으로 보완한다.

### 워치리스트 필드 (A10, 2026-07-16)

`watchlist` — 시그널 탭 관심종목 심볼 배열(예: `["005930.KS","000660.KS","SOXL"]`). 생략하면 앱이
기존 localStorage 워치리스트를 유지하므로, "자산 업데이트" 시에는 보통 생략한다.

## DPS(확정 배당금) 결정 규칙

사이트 index.html의 "💼 내 자산"은 종목별 **확정 DPS(원/주)** 입력을 지원한다(입력 시
월배당 = DPS × 수량, TTM÷12 추정치보다 우선).

1. **확정값 우선**: 해당 기간의 확정된 배당금(공시·확인된 DPS)이 있으면 그 값을 최우선 적용.
2. **없으면 추정**: 조회 시점 주가 × 분배율(등록된 배당률).
3. **미정은 미정으로**: `confirmedDps: 0`이면 사이트가 TTM 추정치로 대체하고 "추정" 라벨을 붙인다 —
   미정임을 지어내지 않는다.
4. **상장 1개월 이내 신규 ETF**(사용자 확정, 2026-07-05): DPS를 미정으로 둔다(추정도 하지 않음).
   첫 분배금이 공시·확정되면 그때 확정 DPS로 반영.
   (예: KIWOOM 코스닥150커버드콜액티브 0198A0 — 2026-06-30 상장, 4계좌 보유, DPS 미정 등록.)

재조회 주기(7일 규칙)와 노션 이력 기록 절차는 `종목조회` 스킬을 참조한다.

## 지급시기(payPeriod) 판정 우선순위

노션 배당기준 마스터(월초 5일 / 월중 15일 / 월말 30일)가 대시보드 HTML의 월별 예상분배금 탭 표기보다
우선한다.

> 잘못 표기돼 있어 월초로 정정했다.
